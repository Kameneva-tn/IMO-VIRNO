# ЇМО ВІРНО — онлайн-магазин молочного та сирів

Статична вітрина з каталогом на 75 товарів, картками товару, кошиком і оформленням замовлення.
Без бекенду: усе працює у браузері, кошик зберігається в `localStorage`.

## Що всередині

```
index.html                 розмітка сторінки
assets/styles.css          стилі (світла тема, темна — через налаштування)
assets/app.js              каталог, фільтри, пошук, картка товару, кошик, оформлення
assets/data/products.json  дані 75 товарів: ціни, описи, склад, харчова цінність, штрихкоди
assets/img/*.webp          фото товарів (60 шт.)
assets/favicon.svg         іконка
server/app.py              приймання замовлень: перевірка, запис, надсилання в Telegram
deploy/imo-virno-api.service  systemd-сервіс обробника
deploy/setup_server.sh     одноразове налаштування VPS
deploy/nginx.conf          конфіг для власного сервера (статика + /api)
deploy/nginx.docker.conf   конфіг для образу Docker
deploy/deploy.sh           оновлення коду на сервері (каталог на сервері не чіпає)
deploy/fetch_data.sh       забрати каталог і фото з сервера собі
Dockerfile                 образ на базі nginx
netlify.toml               налаштування Netlify
vercel.json                налаштування Vercel
.github/workflows/pages.yml  автодеплой на GitHub Pages при пуші в main
```

## Локальний запуск

Каталог підтягується запитом `fetch`, тому файл не можна відкривати як `file://` —
потрібен будь-який локальний сервер:

```sh
python3 -m http.server 8000
# відкрийте http://localhost:8000
```

## Помічник «Допоможи обрати» (Claude)

Кнопка в правому нижньому куті відкриває чат. Помічник питає, чого хочеться
(солоденького, перекус на ходу, замінити каву тощо), уточнює і збирає підбірку.
У підбірці товари можна одразу додавати в кошик; є кнопки «Повернутись до діалогу»,
«Оформити» та «До покупок».

Як це влаштовано: браузер → `POST /api/assistant` → сервер → Claude API.
Claude не бачить каталог цілим шматком, а шукає в ньому через інструмент
`search_catalog`, який виконує наш сервер (`server/assistant.py`). Тож він пропонує
лише реальні товари з реальними цінами; вигадані коди сервер відкидає.

Налаштування в `.env`:

```
ANTHROPIC_API_KEY=sk-ant-...        # console.anthropic.com → API Keys
ANTHROPIC_MODEL=claude-sonnet-5     # або claude-haiku-4-5-20251001 — швидше й дешевше
```

Захист від зловживань: 40 повідомлень за 15 хвилин з однієї адреси, історія діалогу —
до 20 реплік. Характер і правила помічника — текст `SYSTEM` на початку `server/assistant.py`.

## Режим адміна на вітрині

Увійдіть на `/admin/`, потім відкрийте головну сторінку сайту. Зверху з'явиться чорна
панель «Режим адміна», а на кожній картці — кнопка «✎ Редагувати».

- **Редагування картки:** назва, бренд, категорія, підзаголовок, ціна, ваговий товар,
  підпис біля ціни, опис, склад, факти з «+», штрихкод, позначки, розміри, кольори,
  посилання на таблицю розмірів. Зміни видно одразу, покупцям — після оновлення сторінки.
- **Фото:** перетягніть файл у блок фото або виберіть на комп'ютері. Файл автоматично
  перейменовується за схемою `бренд_категорія_назва_штрихкод_код.webp` латиницею,
  наприклад `noco_kondyterski-vyroby-ta-solodoshchi_bilyi-shokolad-z-matcha_4820242820053_3820.webp`.
  Старе фото товару видаляється, а браузери покупців одразу отримують нове.
- **Новий товар:** кнопка «+ Додати товар» на панелі. Обов'язкові внутрішній код і назва;
  фото додається після першого збереження.
- **Видалення:** кнопка «Видалити товар» унизу форми.

Звичайні відвідувачі нічого з цього не бачать: інструменти завантажуються лише
для того, хто увійшов із паролем адміна.

## Адмінка

`http://ваш-сервер/admin/` — вхід за паролем із `ADMIN_PASSWORD` у `.env`.

- **Імпорт таблиці.** Перетягуєте .xlsx з картками, вказуєте підпис розділу — сервер сам
  завантажує фото за посиланнями, розкладає товари по категоріях і дописує в каталог.
  Галочка «спершу перевірка без запису» показує результат, нічого не змінюючи.
- **Товари.** Пошук, фільтр за категорією, окремий фільтр «лише без фото».
  Ціну правлять прямо в рядку, фото додають кнопкою (сервер сам стисне у webp), товар можна видалити.
- **Замовлення.** Останні 30 замовлень — те саме, що надходить у Telegram.

Сесія живе 12 годин, потім треба увійти знову. Вісім невдалих спроб пароля з однієї
адреси блокують вхід на 15 хвилин.

## Як залити нову категорію товарів

У вас є таблиці з картками по категоріях. Найпростіше — через адмінку на `/admin/`. Або командою:

```sh
pip3 install pandas openpyxl pillow                    # один раз
python3 tools/import_xlsx.py ~/Downloads/Мясні_та_ковбаси_картки_товарів.xlsx \
        --section "М'ЯСНІ ПРОДУКТИ ТА КОВБАСИ"
SERVER=root@2.28.7.227 ./deploy/deploy.sh
```

Скрипт сам завантажить фото за посиланнями з таблиці, стисне їх у webp,
розкладе товари по категоріях за ключовими словами в назві й допише все
в `products.json`. Товар із наявним кодом оновлюється, а не дублюється,
тож команду можна запускати повторно після правок у таблиці.

`--category` — категорія з вашого каталогу (26 назв). Вона ж стає підписом у футері картки
і сама визначає, у яку з чотирьох великих груп потрапить товар на сайті.

Структура фільтра задана в `server/importer.py`:
`BIG_GROUPS` — чотири групи вгорі (Їжа, Напої, Краса та здоров'я, Дім і побут),
`CATEGORIES` — 26 категорій каталогу та їхня група.

Назви колонок можуть відрізнятися: імпортер звіряє їх без урахування регістру,
дужок і хвостів на кшталт «— заповнити». Тобто «Опис (чернетка)», «Коди (усі розміри)»
та «Фото (URL) — заповнити» розпізнаються так само, як «Опис», «Код» і «Фото (URL)».
Якщо в клітинці кілька кодів («13467, 13469»), картка буде одна з кодом першого рядка.
Діапазон ціни («109–124») дає мінімальну ціну і підпис «від… до… залежно від розміру».

Одяг: колонки «Розміри» і «Кольори» в таблиці розбираються автоматично
(`S, M, L` або `S / M / L`). Категорія «Одяг, взуття та аксесуари» завжди вимагає вибору.
У кошику кожен розмір-колір — окремий рядок, у замовленні вони йдуть у Telegram.

Позначки на картках («Веган», «Без лактози», «Без глютену», «Без цукру», «Конопляне»,
«Фермерське») проставляються автоматично за назвою, описом і складом — список ознак
у `TAGS` на початку `server/importer.py`. Поле `tags` у `products.json` можна правити руками.

Фільтри на сторінці: вгорі чотири групи, зліва панель із категоріями, позначками та брендами
(множинний вибір, лічильники перераховуються від уже обраних умов і пошуку).
На вузьких екранах панель ховається за кнопкою «Фільтри» з лічильником активних.

## Як оновлювати каталог

Усі дані — в `assets/data/products.json`. Поля одного товару:

| Поле | Призначення |
|---|---|
| `id` | код товару з облікової системи |
| `img` | назва файлу в `assets/img` без розширення; `null` — показується заглушка «фото від постачальника» |
| `full` | `true` — фото заповнює плитку (лайфстайл-кадр), `false` — вписується в білий фон (пакування) |
| `brand`, `cat` | плашки бренду й категорії в картці |
| `cat_name` | категорія з каталогу, напр. «Молочні продукти та сири» — другий ряд фільтрів |
| `g` | велика група: `food`, `drinks`, `care`, `home` — верхній ряд фільтрів |
| `price` | ціна в гривнях, ціле число |
| `pop` | порядок у сортуванні «спочатку популярні» |
| `tag` | підпис у картці справа від ціни, напр. «Ідеально до баношу» |
| `name` | назва; `\n` робить перенос рядка |
| `sub` | підзаголовок: бренд · фасування · країна |
| `desc` | опис |
| `sostav` | склад; `null` — блок не показується |
| `comp` | список фактів із «+»: харчова цінність, зберігання, країна |
| `ean` | штрихкод; малюється як справжній EAN-13, `null` — показується артикул |
| `weighted` | `true` — ціна відображається як грн/кг |
| `sizes`, `colors` | списки доступних розмірів і кольорів (одяг, взуття, аксесуари) |
| `size_chart` | посилання на власну таблицю розмірів; якщо порожнє — показується вбудована |
| `needs_choice` | `true` — без вибору розміру/кольору товар не покласти в кошик |
| `note` | службова позначка зі вихідної таблиці, на сторінці не показується |

Щоб додати товар: покладіть фото в `assets/img/`, додайте об'єкт у `products.json`.
Перебирати код не потрібно — категорії, лічильники й фільтри рахуються з даних.

## Розділи на головній

Плитки під блоком «Хіти тижня» описані списком `SECTIONS` на початку `assets/app.js`:
кожен розділ веде або на групу (`group`), або на перелік категорій (`cats`).
Фото береться з першого товару розділу, кількість рахується автоматично,
порожній розділ показується блідим із підписом «незабаром».
«Акції» шукають товари з полем `sale: true` — поки такого поля немає, розділ порожній.

## Налаштування магазину

У `assets/app.js`, одразу під даними:

```js
const FEAT="15131";          // товар у блоці «Хіти тижня»
const PAIRS=["3664","11788"];// два товари в «Доповніть замовлення»
const FREE=999, SHIP=49;     // безкоштовна доставка від суми, інакше вартість доставки
```

## Замовлення (сервер)

`server/app.py` — обробник на FastAPI. Приймає `POST /api/order`, перевіряє поля,
**сам перераховує суму за `products.json`** (ціни з браузера не приймаються),
записує замовлення в `/var/lib/imo-virno/orders.jsonl` і надсилає його в Telegram
(`TELEGRAM_BOT_TOKEN` + `ADMIN_CHAT_ID` у `.env`).

Розгортання на VPS з Ubuntu:

```sh
SERVER=root@IP TARGET=/var/www/imo-virno ./deploy/deploy.sh   # перше копіювання
ssh root@IP "bash /var/www/imo-virno/deploy/setup_server.sh"  # nginx + venv + systemd
ssh root@IP "nano /var/www/imo-virno/.env"                    # токени
ssh root@IP "systemctl restart imo-virno-api"
```

**Де живуть дані.** Після першого розгортання каталог `assets/data/products.json`
і фото на сервері стають джерелом правди: адмінка пише саме туди. `deploy.sh` їх не
перезаписує, а `fetch_data.sh` забирає назад на Mac, щоб покласти в git.

Перевірка: `curl -s http://IP/api/health` → `{"ok":true,"products":75,"telegram":true}`.
Логи: `journalctl -u imo-virno-api -f`. Оновлення сайту — знову `./deploy/deploy.sh`.

Локально: `ORDERS_DIR=./orders SERVE_STATIC=1 uvicorn server.app:app --port 8085`.
